# 엔티티·관계 추출 프롬프트 초안 (GraphRAG)

목요일 작업용 **초안**입니다. 아직 한 청크도 돌려보지 않았고 정밀도·재현율을 측정한 적이 없습니다.

## 설계 의도 한 줄

**훈련(행동) 노드와 의료(질환·증상) 노드를 타입 레벨에서 분리한다** — 훈련으로 풀 문제와
수의사에게 보내야 할 문제를 그래프 구조에서 구분해야, "엉덩이를 끄는데 짖음 교정을 먼저
할까요"(Q11) 같은 질문에서 감별 경로를 밟을 수 있습니다. 타입이 섞이면 이 분기가
프롬프트 문구에만 남고 검증할 수 없게 됩니다.

## 노드 타입 8종

| 타입 | 무엇 | 예 |
|---|---|---|
| `문제행동` | 보호자가 고치고 싶어하는 행동 | 입질, 줄 당김, 요구성 짖음 |
| `훈련법` | 이름 붙은 절차·기법 | 타임아웃, 둔감화, 멈춰 서기 |
| `증상` | 몸 상태의 관찰 가능한 신호 | 엉덩이 끌기, 머리 흔들기, 절뚝임 |
| `질환` | 진단명 | 슬개골 탈구, 외이도염, 인지기능장애 |
| `견종` | 품종 | 푸들, 비숑, 포메라니안 |
| `연령대` | 생애 단계 | 4개월, 노령견, 성견 |
| `용품` | 도구·장비 | 켄넬, 가슴줄, 클리커 |
| `원칙` | 절차가 아닌 규칙·기준 | 보상 타이밍, 일관성 |

`문제행동`과 `증상`의 경계가 이 스키마에서 가장 미끄러운 지점입니다. 판정 기준은
**교정 대상인가, 관찰 소견인가**입니다. 짖음은 보호자가 고치려는 행동이면 `문제행동`,
통증의 신호로 언급되면 `증상`입니다. 같은 표현이 문맥에 따라 갈립니다.

## 엣지 타입 5종

| 타입 | 방향과 의미 |
|---|---|
| `완화한다` | (훈련법\|원칙) → (문제행동\|증상). A를 하면 B가 줄어든다 |
| `악화시킨다` | (훈련법\|원칙\|용품) → (문제행동\|증상). A를 하면 B가 심해진다 |
| `선행조건` | X → (훈련법). 훈련법을 적용하기 전에 갖춰져야 하는 것 |
| `금기` | X → (훈련법). 이 조건에서는 그 훈련법을 쓰면 안 된다 |
| `감별필요` | (증상\|문제행동) → (질환). 훈련 전에 의료 감별이 필요하다 |

`감별필요`가 위 설계 의도를 실행하는 엣지입니다. 이 엣지는 **반드시 증상/문제행동에서
질환으로** 향하고, 훈련법 노드를 거치지 않습니다.

`금기`와 `선행조건`은 반대가 아닙니다. 선행조건이 빠지면 훈련이 덜 듣고, 금기를 어기면
상태가 나빠집니다. 문서가 둘을 구분하지 않으면 `선행조건`으로 두고 넘어가세요.

## ASR 정규화 지침

이 코퍼스는 유튜브 STT라 ASR 오기·발음 뭉개짐이 있다. 표기가 아니라 문맥으로 엔티티를
판정해 표준 용어로 정규화하고, `normalized_from` 필드에 원표기를 기록하라.
예: `'분리브라인'` → `'분리불안'`. 문맥으로도 확신이 없으면 추출하지 말 것.

정규화하지 않았으면 `normalized_from`은 `null`입니다. 원표기를 남기는 이유는
정규화가 틀렸을 때 되짚을 수 있어야 하기 때문이고, 이 필드가 비어 있으면
잘못된 병합을 나중에 찾아낼 방법이 없습니다.

## 출력 스키마

청크 하나당 JSON 객체 하나. `entities`와 `relations` 두 키만 최상위에 둡니다.

```json
{
  "entities": [
    {
      "name": "분리불안",
      "type": "문제행동",
      "normalized_from": "분리브라인",
      "evidence": "얘가 분리브라인이 좀 있어 가지고 현관 앞에서 계속 서성거려요",
      "confidence": "high"
    },
    {
      "name": "켄넬",
      "type": "용품",
      "normalized_from": null,
      "evidence": "켄넬 문을 바로 닫으면 안 되고요",
      "confidence": "high"
    },
    {
      "name": "켄넬 훈련",
      "type": "훈련법",
      "normalized_from": null,
      "evidence": "켄넬 문을 바로 닫으면 안 되고요",
      "confidence": "medium"
    }
  ],
  "relations": [
    {
      "source": "분리불안",
      "target": "켄넬 훈련",
      "type": "금기",
      "evidence": "분리불안이 있는 애한테 문부터 닫아버리면 더 심해집니다",
      "confidence": "high"
    }
  ]
}
```

규칙:

- `evidence`는 **청크 본문에서 그대로 잘라온 문자열**입니다. 요약하거나 다듬지 마세요.
  근거 문장을 만들어낼 수 있으면 추출 전체를 신뢰할 수 없습니다.
- `relations`의 `source`/`target`은 같은 청크의 `entities`에 있는 `name`이어야 합니다.
  청크 밖 엔티티와는 연결하지 않습니다 (그래프 병합 단계에서 붙입니다).
- `confidence`는 `high` / `medium` / `low`. 문맥으로 확신이 없으면 추출하지 않는 것이
  원칙이므로, `low`는 "추출은 하되 사람이 봐야 함"이라는 뜻으로만 씁니다.
- 추출할 것이 없으면 빈 배열을 반환합니다. 채우려고 만들지 마세요.
- 훈련 절차·방법을 독립적으로 다루는 문서가 아닌 이상, 범용 격려·태도 발화에서
  훈련법 엔티티를 추출하지 마세요. 예: '삐지면 안돼요', '다시 하면 돼요'는 훈련법이
  아닙니다.

## 아직 정하지 않은 것

- 청크 경계를 넘는 관계를 어느 단계에서 붙일지 (추출 시 vs 병합 시)
- 동일 엔티티 병합 키 — `name` 문자열인지, 정규화 사전 id인지
- `confidence`를 그래프 가중치로 쓸지, 필터로만 쓸지
- 이 프롬프트를 적용할 모델과 청크 단위 (현재 코퍼스는 target 420자 청킹)
