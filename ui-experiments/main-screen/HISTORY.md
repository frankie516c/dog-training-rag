# HISTORY — 메인 화면 캐릭터 디자인 실험

이 문서는 이 폴더를 처음 보는 사람도 배경지식 없이 따라올 수 있도록 쓴 작업 일지다. 날짜는 모두 2026-08-24, Claude Code 세션 기준.

## 0. 이게 뭐 하는 폴더인가

`dog-training-rag-retrieval`은 강아지 훈련 지식을 검색해서 답해주는 RAG(검색 증강 생성) 백엔드 프로젝트다. 지금까지는 Python 백엔드와 데이터 파이프라인 위주였고, 사용자가 직접 보는 화면(프론트엔드)은 없었다. 이 폴더는 그 앱의 **메인 화면**을 어떻게 만들지 — 특히 화면 한가운데를 차지할 **강아지 캐릭터**를 어떤 방식으로 그리고 움직일지 — 정하기 위한 디자인 실험 기록이다.

## 1. 최초 요구사항 (사용자가 준 원문 그대로 정리)

> "이 레포에 맞는 메인 화면을 개발할 것이다. 귀여운 캐릭터 디자인이 최종 목표다. 이를 위해 3가지 실험을 한다."

사용자는 참고 이미지 3장과 함께 아래 3가지 실험 아이디어를 제시했다.

**참고 이미지**
- 이미지 1: 도트(픽셀) 스타일로 그려진 강아지 3마리 예시 (시바견/몰티즈 느낌의 작은 강아지들, 8~16px급 도트 그래픽)
- 이미지 2: 도트 스타일로 그려진 방 인테리어 예시 (창문, 책상, 침대, 곰인형, 캐리어 가방 등이 도트로 그려진 방)
- 이미지 3: **"댕스(DAENGS)"라는 실제 서비스로 보이는 모바일 앱 화면 캡처**. 상단에 로고와 홈/기록/알림/프로필 아이콘, 중앙에 정사각형에 가까운 "방 안에 강아지가 있는" 3D 느낌의 일러스트 카드(창문·화분·조명·강아지집·러그가 있는 방, 그 안에서 노는 푸들), 그 아래 "무엇이든 물어보세요" AI 챗봇 입력창과 추천 질문 칩, 오늘의 산책 요약 통계 카드, 맨 아래 홈/산책기록/커뮤니티/마이 4개 탭의 하단 내비게이션으로 구성됨

사용자는 이미지 3을 **"이 UI가 기본 틀이 될 것"**이라고 못박았다 — 즉 레이아웃 구조(상단바 → 방 안 강아지 카드 → AI 챗봇 입력창 → 통계 카드 → 하단 내비)는 그대로 가져가고, **"방 안 강아지" 부분을 어떤 기술/그림 스타일로 만들지**가 이번 실험의 진짜 주제다.

**실험 1 — 도트(픽셀) 버전**: 이미지 1처럼 강아지를 도트로, 이미지 2처럼 방도 도트로 그려서 조합.

**실험 2 — 포즈 애니메이션 버전** (이후 폐기됨): 강아지 파츠(귀, 다리, 꼬리 등)를 SVG로 따로 만들어 관절처럼 조립하는 방식이 **아니라**, "갸우뚱", "꼬리 흔들기" 같은 정해진 동작 하나하나를 통째로 미리 그려두고, 그 그림들을 전환해가며 강아지가 방 안에서 노는 것처럼 보이게 하는 방식.

**실험 3 — krea2 + 2D 리깅 버전**: krea2(AI 이미지 생성 서비스, 아래 5절 참고)로 원하는 그림체의 강아지 이미지를 뽑고, 그와 비슷한 견종을 미리 만들어둔 프리셋 중에서 찾아 매칭한 뒤, 2D 리깅(파츠별로 뼈대를 심어 회전·이동시키는 애니메이션 기법)으로 그 강아지의 머리·귀·꼬리 등을 자연스럽게 움직이게 만드는 방식.

사용자는 "질문이 있으면 중간중간 물어보되, 디자인적인 선택지를 물을 땐 화면으로 비교안을 띄워서 물어봐 달라"고 요청했다.

## 2. 진행 방식 결정

바로 코드를 짜기 전에 두 가지를 먼저 정했다.

- **3개 실험을 순차적으로 하나씩 깊게 만들지, 러프하게 동시에 만들어 비교할지** → **동시에 러프하게 비교**하는 쪽으로 결정
- **지금 단계의 결과물 범위를 어디까지로 할지** (레포에 실제 프론트엔드 코드를 세팅할지, 아니면 시각적 비교만 먼저 할지) → **claude.ai Artifact(웹에 바로 띄워보는 목업 페이지)로 비교만 먼저** 하기로 결정. 레포 코드는 건드리지 않기로 함.

이 결정에 따라 처음에는 레포에 아무 커밋도 하지 않고, claude.ai Artifact 링크로만 결과물을 주고받았다. (나중에 "GitHub에 올려서 비교하고 싶다"는 요청으로 이 브랜치가 만들어졌다 — 6절 참고.)

## 3. v1 — 3개 실험을 한 화면에 비교한 첫 목업

파일: `drafts/v1-three-experiments.html`

기본틀(이미지 3 레이아웃)에서 상단 로고/아이콘, AI 채팅 입력바, 산책 요약 통계 카드, 하단 내비게이션은 세 실험 모두 똑같이 두고, **"방 안 강아지" 영역만** 세 가지 방식으로 다르게 만들어 폰 화면 모양 카드 3개를 나란히 배치했다. 셋 다 이 단계에서는 진짜 프로덕션 코드가 아니라 "톤이 어떻게 보이는지"를 확인하기 위한 순수 HTML/CSS/JS 목업이다.

### 실험 1 — 도트: 어떻게 그렸나

- **방**: HTML `<div>` 여러 개를 겹쳐 쌓고, CSS `background`와 `box-shadow`만으로 만들었다. 하늘은 `repeating-linear-gradient`로 8px 줄무늬를 반복시켜 도트 느낌의 하늘을, 창문은 `box-shadow`를 이중으로 둘러 두꺼운 픽셀 테두리를 흉내 냈고, 바닥은 가로 방향 `repeating-linear-gradient`로 나무 바닥 타일을, 러그는 CSS `clip-path`로 팔각형(계단식 원)을 잘라내 픽셀 느낌의 둥근 모양을 만들었다.
- **강아지**: 이미지가 아니라 **HTML `<canvas>`에 JavaScript로 매 프레임 직접 그린 것**이다. 20×18칸짜리 격자를 만들고, 각 칸이 강아지 몸의 어느 부위에 속하는지를 좌표 수식(타원 안에 있는지 판별하는 `(x-중심)²/반지름² ≤ 1` 공식)으로 계산해서 자동으로 채웠다 — 즉 강아지 그림을 손으로 한 칸씩 그린 게 아니라 "머리는 이 좌표를 중심으로 한 원, 몸통은 이 좌표를 중심으로 한 타원, 귀는 그 옆에 작은 타원 두 개" 식으로 도형 규칙을 코드로 적어서 캔버스가 계산해 그리게 했다. 이렇게 하면 좌우 대칭이 자동으로 맞는다. 눈·코·볼터치·목줄은 정해진 칸에 직접 색을 지정했다. 캔버스는 `image-rendering: pixelated`를 줘서 확대해도 부드럽게 뭉개지지 않고 각진 픽셀 그대로 보이게 했다. 눈 깜빡임(3.2초마다 눈 색을 잠깐 살색으로 바꿈)과 꼬리 흔들기(0.55초마다 꼬리 위치를 한 칸씩 좌우로 바꿈)는 `setInterval`로 격자를 다시 그리는 방식으로 구현했다.

### 실험 2 — 포즈 스왑: 어떻게 그렸나 (v2에서 폐기됨)

- **방**: 실험 1과 달리 각진 도트가 아니라 둥근 모서리(`border-radius`)와 그라데이션을 쓴 "플랫 일러스트" 느낌으로 만들었다. 창문은 위쪽만 둥근 사각형, 구름은 흰 타원, 화분은 줄기+잎 모양의 작은 도형 조합.
- **강아지**: 세 가지 자세("대기", "고개 갸우뚱", "꼬리 흔들기")를 **SVG로 각각 통째로 손으로 그렸다.** `<ellipse>`(타원)와 `<circle>`(원), `<path>`(곡선 경로)만 조합해서 얼굴·귀·몸통·꼬리 좌표를 하나하나 지정했고, 자세마다 귀 각도나 꼬리 위치, 입 모양이 다른 별도의 SVG 그림이었다 — 파츠를 관절로 연결해 움직인 게 아니라 **그림 자체가 3장 따로** 있는 것이다. CSS `@keyframes`로 세 SVG의 `opacity`(투명도)를 6초 주기로 번갈아 0↔1로 바꿔서, 마치 애니메이션처럼 자세가 전환되는 것처럼 보이게 했다. 실제로는 트윈(중간 동작 보간)이 없어서 자세가 "뚝뚝 끊기며" 바뀐다.

### 실험 3 — 2D 리깅 개념 목업: 어떻게 그렸나

- **방**: 실험 1·2보다 그림자와 그라데이션을 더 써서 입체감을 살렸다. 창문에 `radial-gradient`로 하늘 느낌을 주고, 액자·선반·러그·베드에 각각 그림자(`box-shadow`)를 넣어 이미지 3(댕스 앱)에 가까운 "포근한" 톤을 냈다.
- **강아지**: 하나의 SVG 안에서 몸통·머리·왼쪽 귀·오른쪽 귀·꼬리를 각각 별도의 `<g>`(그룹) 태그로 분리했다. 각 그룹에 `transform-origin`(회전 중심점, 예: 귀는 귀뿌리 쪽)을 지정하고, CSS `@keyframes`로 그룹마다 **다른 주기·다른 폭으로** `rotate()`나 `translateY()`를 반복시켰다 — 몸통은 2.8초 주기로 살짝 커졌다 작아지며 숨쉬는 것처럼, 머리는 2.6초 주기로 까딱까딱, 양쪽 귀는 서로 다른 3.1초/2.7초 주기로 팔랑팔랑, 꼬리는 1.1초의 빠른 주기로 좌우로 흔들리게 했다. **이건 진짜 "리깅"은 아니다** — 진짜 2D 리깅이라면 뼈대(본)에 이미지 파츠를 매달아 역운동학 등으로 자연스럽게 연결하는데, 여기서는 그냥 SVG 도형을 손으로 나눠서 각자 CSS 애니메이션을 준 것뿐이다. 사용자가 실제로 만들고 싶어하는 "krea2 이미지 → 프리셋 매칭 → 2D 리깅"이 어떤 느낌일지 **개념만 미리 보여주는 목업**이다.

## 4. v2 — 실험 2 폐기, 실험 1 다듬기

사용자 피드백: "실험 1, 3만 살린다(실험 2는 뺀다). krea2는 로컬 설치 가능한지 PC 사양부터 확인해달라. 도트는 강아지 비율은 좋으니, 기본틀 UI(이미지 3)처럼 소품을 더 많이 똑같이 도트로 넣고, 강아지 전체 크기는 조금 줄여보자."

파일: `drafts/v2-dot-and-rig.html`

- 실험 2(포즈 스왑)의 SVG 3장, `il-*` CSS 클래스, `pose-idle/tilt/wag` 키프레임을 모두 삭제
- 실험 1 방에 소품 6개 추가: 문(`.pix-door`, 손잡이 포함), 환영 매트(`.pix-mat`, 줄무늬 패턴), 액자(`.pix-frame`, 이중 테두리 + 안쪽 그림), 선반(`.pix-shelf`)과 그 위의 공(`.pix-ball`), 화분(`.pix-plant`, 화분+잎 2장) — 전부 이미지 3(댕스 앱)의 소품 밀도(창문+액자+선반+화분+문+매트)에 맞춰 CSS 사각형/원 조합으로 만들었다
- 강아지 크기 축소: Canvas 격자 셀 크기를 9px → 7px로 줄였다. 격자 칸 수(20×18)와 도형 좌표 규칙은 그대로 둔 채 "셀 하나가 차지하는 실제 픽셀 크기"만 줄였기 때문에, 강아지의 가로세로 비율과 생김새는 그대로고 화면에서 차지하는 크기만 작아졌다.

## 5. krea2가 뭔지 확인 + 이 PC에 설치 가능한지 조사

실험 3을 진짜로 구현하려면 krea2 연동이 필요해서, 지금 작업 중인 PC에 krea2 모델을 직접 설치해서 돌릴 수 있는지 확인했다.

**이 PC(작업 데스크톱) 사양**
- CPU: Intel i7-8700 (6코어 12스레드, 3.2GHz, 2017년형)
- RAM: 16GB (8GB×2, 4개 슬롯 중 2개 사용 — 증설 여지 있음), 조사 시점 여유 약 7GB
- GPU: NVIDIA RTX 3050, **VRAM 6GB** (여유 5.2GB)
- 디스크: C드라이브 139GB 여유
- 네트워크: 정상 (huggingface.co 응답 116ms)

**krea2가 실제로 뭔지** (공식 문서 `krea.ai/docs/ko/developers/krea-2/overview` + Hugging Face 확인)
- Krea 2는 **텍스트를 이미지로 바꿔주는 생성 모델**이고, `krea/Krea-2-Raw`(기본형)와 `krea/Krea-2-Turbo`(8단계로 빠르게 뽑는 증류형) 두 종류가 있다
- 파라미터 수(모델의 크기를 나타내는 지표)가 **130억 개(13B)** — FLUX 같은 최신 고성능 이미지 생성 모델과 비슷한 규모의 "무거운" 모델이다
- 기본 사용 방법은 krea.ai가 호스팅하는 API를 호출하는 것이고, 원한다면 모델 파일을 직접 받아 내 컴퓨터에서 돌리는 것(셀프호스팅)도 지원한다 — 원본(fp16) 그대로 쓰면 매우 크지만, 크기를 줄인(양자화) 버전도 공개돼 있다: Q2_K(4.89GB)부터 Q8_0(13.7GB)까지 다양한 압축 단계가 있다

**결론**: 이 PC의 병목은 GPU VRAM 6GB다. 가장 작게 압축한 Q2_K(4.89GB)조차 모델 가중치만 겨우 VRAM에 들어가는 수준이고, 실제 이미지 생성에는 그 외에도 텍스트 인코더·VAE·연산 중 임시 메모리가 추가로 더 필요해서 여유가 거의 없다. 억지로 돌릴 수는 있어도 그림 품질이 눈에 띄게 떨어지고 이미지 한 장에 수 분씩 걸릴 가능성이 높다. **"사양이 똑같은 새 PC"로 바꿔도 결론은 같다** — VRAM 6GB는 GPU 칩에 고정된 값이라 어느 컴퓨터든 동일하게 병목이 된다(RAM 여유만 조금 나아질 뿐). 그래서 **krea2는 로컬 설치보다 krea.ai가 제공하는 호스팅 API를 그대로 호출하는 방식으로 연동하는 것을 권장**한다. 반면 실험 3의 나머지 두 단계 — "생성된 이미지와 비슷한 견종을 프리셋에서 찾아 매칭하는 모델"과 "2D 리깅에 필요한 관절 위치 추정 모델" — 은 krea2보다 훨씬 작은 모델일 가능성이 높아서 이 GPU로도 충분히 돌아갈 것으로 예상된다 (아직 구체적으로 조사는 안 함).

## 6. 이 브랜치 — GitHub에서도 비교할 수 있게 정리

여기까지는 레포에 커밋 없이 claude.ai Artifact 링크로만 목업을 주고받았는데, "여기서 작업한 것들을 GitHub에서도 비교할 수 있게 브랜치를 파서 초안들을 다 올려달라"는 요청을 받아 `experiment/main-screen-character-mockups` 브랜치를 새로 만들어 다음을 커밋했다.

- 1번째 커밋: v1(3개 실험 비교본)
- 2번째 커밋: v2(실험 2 삭제 + 실험 1 다듬기) + 이 `HISTORY.md` + `STATUS.md`

두 커밋을 GitHub에서 비교(diff)하면 v1→v2 사이에 무엇이 왜 바뀌었는지 그대로 볼 수 있다. `main` 브랜치는 이 작업으로 전혀 건드리지 않았다.

한 가지 참고: 이 레포 `.gitignore`에는 원래 `*.html`을 전부 무시하는 규칙이 있었다(발표 문서를 마크다운에서 HTML로 렌더링한 빌드 산출물을 걸러내기 위한 규칙). 이번 목업 HTML은 그런 빌드 산출물이 아니라 손으로 직접 작성한, 그 자체가 소스인 파일이라서 `!ui-experiments/**/*.html` 예외 규칙을 한 줄 추가해서 같이 커밋했다.
